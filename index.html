Introducción

📦

¿Qué son?

Las estructuras de datos son formas de organizar y almacenar información en la memoria de un computador para que pueda ser accedida y modificada de manera eficiente.

Piénsalas como contenedores especializados: igual que en una cocina tienes ollas, sartenes y recipientes para distintos propósitos, en programación tienes arrays, listas, pilas, etc.

🎯

¿Para qué sirven?

  • Organizar datos de forma lógica y eficiente
  • Acelerar búsquedas, inserciones y eliminaciones
  • Resolver problemas complejos con algoritmos óptimos
  • Optimizar el uso de memoria del programa
  • Modelar situaciones del mundo real (redes, árboles, colas)

Arrays

Acceso O(1)

Definición

Un array (arreglo) es una colección de elementos del mismo tipo almacenados en posiciones de memoria contiguas. Cada elemento tiene un índice numérico que empieza en 0.

Explicación simple

Imagina una fila de casilleros numerados en un gym. Cada casillero tiene un número (índice) y dentro guardas algo. Para acceder al casillero 5, vas directamente al número 5 — sin buscar uno por uno.

Acceso rápido O(1) Tamaño fijo Índice desde 0

int[] arr = {15, 42, 8, 99, 3};

    System.out.println(arr[i]);
}
02

Listas Enlazadas

Dinámica

Definición

Una lista enlazada es una colección de nodos donde cada nodo contiene un dato y una referencia (puntero) al siguiente nodo. A diferencia de los arrays, los nodos no están en posiciones contiguas de memoria.

🔗 Simple

Cada nodo apunta solo al siguiente. El último nodo apunta a null.

A→
B→
C→
null

🔗🔗 Doble

Cada nodo apunta al siguiente Y al anterior. Permite recorrido en ambas direcciones.

←A→
←B→
←C→

🔄 Circular

El último nodo apunta de vuelta al primero. Forma un ciclo continuo.

A→
B→
C↩

Ejemplo en código

// Nodo de lista simple en Java
class Nodo {
    int dato;
    Nodo siguiente;

    Nodo(int dato) {
        this.dato = dato;
        this.siguiente = null;
    }
}

// Crear lista: 10 → 20 → 30
Nodo head = new Nodo(10);
head.siguiente = new Nodo(20);
head.siguiente.siguiente = new Nodo(30);
03

Pilas (Stack)

LIFO

Definición

Una pila es una estructura LIFO: Last In, First Out (último en entrar, primero en salir). Solo puedes agregar o quitar elementos por la cima (top).

Explicación simple

Como una pila de platos: pones platos encima y siempre tomas el de arriba primero. No puedes sacar el del fondo sin quitar los de encima.

push() — agregar pop() — quitar peek() — ver cima

Usos reales

  • Ctrl+Z (deshacer) en editores de texto
  • Historial de navegación (botón "atrás")
  • Llamadas a funciones en la memoria
  • Evaluación de expresiones matemáticas

Visualización

🟠 C ← TOP (último en entrar)
🟡 B
🔵 A ← primero en entrar
▬▬▬ BASE ▬▬▬

pop() saca C primero (LIFO)

// Java — Stack
Stack<Integer> pila = new Stack<>();
pila.push(10);  // [10]
pila.push(20);  // [10, 20]
pila.push(30);  // [10, 20, 30]

pila.pop();     // retorna 30 ← LIFO
pila.peek();    // retorna 20 (sin quitar)

// Java — Queue
Queue<String> cola = new LinkedList<>();
cola.offer("A");  // enqueue
cola.offer("B");
cola.offer("C");

cola.poll();   // retorna "A" ← FIFO
cola.peek();   // retorna "B" (sin quitar)

Definición

Una cola es una estructura FIFO: First In, First Out (primero en entrar, primero en salir). Los elementos entran por el rear (final) y salen por el front (frente).

Explicación simple

Como una fila en el banco o supermercado: el primero que llega es el primero en ser atendido. Nadie puede "colarse" al frente.

enqueue() — agregar dequeue() — quitar

Variantes

  • Cola simple: FIFO estándar
  • Cola doble (Deque): entrada/salida por ambos extremos
  • Cola de prioridad: sale el de mayor prioridad primero

Tablas Hash

Búsqueda O(1)

Definición

Una tabla hash (hash table) almacena pares clave → valor. Usa una función hash que convierte la clave en un índice numérico para ubicar el valor directamente en memoria.

Explicación simple

Es como un diccionario: buscas la palabra (clave) y obtienes su definición (valor) directamente, sin leer todo el diccionario. La función hash es el "alfabeto" que te dice en qué página buscar.

put(clave, valor) get(clave) Colisiones

HashMap<String, String> tabla = new HashMap<>();

tabla.get("nombre"); // → "Ana"  O(1)

⚠️ Colisiones

Una colisión ocurre cuando dos claves distintas producen el mismo índice. Soluciones: encadenamiento (lista en cada celda) o sondeo lineal (buscar la siguiente celda libre).

06

Árboles Binarios / BST / AVL

Jerárquico

Definición

Un árbol es una estructura jerárquica de nodos. Cada nodo tiene un valor y puede tener nodos hijo. El nodo superior es la raíz (root). En un árbol binario, cada nodo tiene máximo 2 hijos (izquierdo y derecho).

🌳 Árbol Binario

Cada nodo tiene máximo 2 hijos. No hay reglas de orden.

🔍 BST (Binary Search Tree)

Regla de orden: izquierda < raíz < derecha. Permite búsqueda eficiente O(log n).

30 < 50 < 70 ✔

⚖️ AVL (Balanceado)

BST que se autobalancea. La diferencia de altura entre subárboles es máximo 1. Evita degradarse a O(n).

❌ Sin balance
✅ AVL

Código BST — Búsqueda

// Java — Búsqueda en BST
int buscar(Nodo raiz, int valor) {
    if (raiz == null) return -1;           // no encontrado
    if (valor == raiz.dato) return valor;  // encontrado!
    if (valor < raiz.dato)
        return buscar(raiz.izq, valor);    // ir a la izquierda
    else
        return buscar(raiz.der, valor);    // ir a la derecha
}
07

Grafos

Redes y Rutas

Definición

Un grafo es una estructura compuesta por vértices (nodos) y aristas (conexiones). Permite modelar redes, relaciones y rutas entre entidades.

Formalmente: G = (V, E) donde V = vértices y E = aristas.

Tipos de grafos

  • Dirigido: las aristas tienen dirección (A → B)
  • No dirigido: conexión en ambas direcciones (A — B)
  • Ponderado: las aristas tienen peso/costo
  • Cíclico/Acíclico: con o sin ciclos

Usos reales

  • Google Maps — rutas entre ciudades
  • Redes sociales — amigos de amigos
  • Internet — routers y conexiones
  • Juegos — mapas y niveles

Visualización

// Representación: Lista de adyacencia
Map<String, List<String>> grafo = new HashMap<>();
grafo.put("A", Arrays.asList("B", "C"));
grafo.put("B", Arrays.asList("A", "D"));
grafo.put("C", Arrays.asList("A", "E"));
// Recorrido BFS o DFS

Complejidad Algorítmica — Big O

Eficiencia

¿Qué es Big O?

La notación Big O describe cómo crece el tiempo de ejecución (o el espacio en memoria) de un algoritmo en función del tamaño de la entrada n. Nos permite comparar algoritmos sin depender del hardware.

O(1)
Constante

El tiempo no cambia sin importar el tamaño. El mejor caso posible.

Acceso a arr[5], get(clave) en HashMap
O(log n)
Logarítmica

El problema se divide a la mitad en cada paso. Muy eficiente.

Búsqueda binaria, búsqueda en BST
O(n)
Lineal

El tiempo crece proporcional a la entrada. Recorrer todos los elementos.

Recorrido de lista, búsqueda lineal
O(n log n)
Log-lineal

Algoritmos de ordenamiento eficientes como Merge Sort.

Merge Sort, Heap Sort, Quick Sort (promedio)
O(n²)
Cuadrática

Dos bucles anidados. Lento con datos grandes.

Bubble Sort, Selection Sort, comparar todos con todos
O(2ⁿ)
Exponencial

Crece muy rápido. Impracticable con entradas grandes.

Fibonacci recursivo sin memoización, fuerza bruta

// Ejemplos de complejidad en Java

// O(1) — acceso directo
int x = arr[0];

// O(n) — recorrer lista
for (int i = 0; i < n; i++) { ... }

// O(n²) — doble bucle anidado
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++) { ... }

// O(log n) — búsqueda binaria
while (low <= high) {
    int mid = (low + high) / 2;
    // ... divide a la mitad
}
